# GOLF ESCAPE AI（仮称）第1段階：静止画解析の試作版

林の写真の上で木の位置を指定すると、木の間を通過できそうな方向と、スコア帯別の推定確率を表示するスマートフォン向けWebアプリ（PWA）です。

この版は開発指示書の「第1段階」にあたります。AIによる自動検出とリアルタイム解析は未実装です。

## 起動方法

Node.js 20 以上が必要です。

```bash
npm install
npm run dev        # 開発用サーバー（http://localhost:5173）
npm run build      # 本番用ファイルを dist/ に出力
npm run preview    # dist/ を手元で確認
npm test           # 計算ロジックの単体テスト
```

スマートフォンでカメラを使うには、HTTPS で配信する必要があります（ブラウザーの仕様）。
`dist/` フォルダーの中身を、HTTPS に対応した静的ホスティングにそのまま置けば動きます。
リポジトリの `docs/` はビルド済みなので、試すだけならビルドは不要です。

### GitHub Pages で公開する

`docs/` フォルダーに、公開用のビルド済みファイルを入れてあります。次の設定をすると、
`https://<ユーザー名>.github.io/<リポジトリ名>/` で開けるようになり、スマートフォンでカメラも使えます。

1. GitHub のリポジトリで「Settings」→「Pages」を開く
2. 「Source」を「Deploy from a branch」にする
3. 「Branch」を `main`、フォルダーを `/docs` にして「Save」を押す
4. 1〜2分後に、同じ画面に表示されるURLを開く

ソースを変更したときは、`npm run build:pages` で `docs/` を作り直してからコミットします。

### ビルドについての注意

このプロジェクトは React + TypeScript + Vite の構成です。ただし、作成時の環境では npm レジストリに接続できず、
Vite をインストールできませんでした。そのため同梱のビルド済みファイルは、同じソースを esbuild で直接ビルドしたものです
（`node scripts/build.mjs`）。`npm run dev` と `npm run build`（Vite）は、設定は標準的な内容ですが未実行です。
Vite でうまく動かない場合は、`npm run build:esbuild` と `npm run serve:dist` が代わりに使えます。
`docs/`（GitHub Pages 用）も、同じ esbuild のビルドで作っています。

## 実装済みの機能

- 利用上の注意（用途、ゴルフ規則、安全、確率の位置づけ）の表示
- 平均スコア（70台〜120台）の選択と端末内への保存、設定からの変更
- 背面カメラの起動、静止画の撮影、撮影画像の確認、再撮影
- 端末内の画像の読み込み（カメラを使えない場合の代替）
- 暗い写真、ブレ・ピンぼけの可能性がある写真への警告
- 障害物の手動指定：幹、枝（下端の高さ付き）、地面の障害物。選択、削除、1つ戻す、全消去
- 指定した障害物からの候補ルートの計算（最大3件）と、写真上への矢印・帯・ラベルの表示
- スコア帯、ライ、距離、クラブに応じた推定確率（仮モデル）
- 判定不能の表示（障害物なし、枝がかかるのに距離・クラブが未入力）
- 通過不可の隙間を候補から外す処理
- 安全確認（前方に人がいる・確認できない場合はルートを表示しない）
- PWA（ホーム画面への追加、2回目以降のオフライン起動）

## 未実装の機能

- AIによる木・障害物の自動検出（第2段階）
- カメラをかざしたままのリアルタイム解析（第3段階）
- 人やカートの自動検出（現在は利用者の自己申告）
- 「対象が遠すぎる」ことの検出
- 奥行きの推定、クラブ別の球筋、実測データによる確率の補正（第4段階）
- ボールを出したい方向の個別指定（現在は写真の中心を基準に、各隙間の向きを表示）

## 計算の考え方

1. 写真の横位置を、ボール付近から見た左右の角度に変換する（画角は仮定。設定で変更可能）。
2. 幹・地面の障害物がふさぐ角度の範囲を除いた残りを「隙間」とする。
3. 隙間の両側から、指定のずれ（0.5°）とボール半径分の余裕を引く。余裕を引いて残らない隙間は通過不可とする。
4. 打ち出し方向のばらつきを正規分布とみなし、隙間に収まる割合を求める。狙う方向は、この割合が最大になる向きを探す。
5. 枝がかかる範囲では、打ち出し高さが枝の下に収まる割合を掛ける（距離とクラブが必要。未入力なら判定不能）。
6. 大きなミス（チョロなど）の割合を差し引く。

表示する数値は「木の間を通過する推定確率」であり、林から完全に脱出できる確率ではありません。

### 仮パラメータ

スコア帯別のばらつき、ライの倍率、クラブ別の打ち出し角、色分けのしきい値などは、すべて
`src/model/params.ts` にまとめてあります。**実測データによる検証は行っていない仮の値です。**
アプリの設定画面でも、現在の値を一覧できます。

### この計算の限界

- 写真に写っていない範囲、指定していない奥の木や枝は計算に含まれません。
- 画角は機種やカメラのモードで変わります。仮定がずれると、角度の換算もずれます。
- カメラがボールの真上付近にあり、ほぼ水平に構えている前提です。離れた位置や大きく傾けた写真では誤差が増えます。
- 枝の高さの判定は、弾道を直線とみなした近似です。距離は「最初の木までの距離」を全障害物に共通で使います。

## 構成

```
src/
  model/        計算ロジック（画面に依存しない純粋な関数）
    params.ts     仮パラメータ
    geometry.ts   写真の位置と角度の変換、正規分布
    routes.ts     障害物 → 候補ルートと推定確率
    describe.ts   表示用の文言
    routes.test.ts 単体テスト
  analysis/     障害物の検出元のインターフェース（第2・第3段階で実装を追加）
  camera/       カメラの起動・停止、フレームの取り出し
  image/        画像の読み込み、明るさ・ブレの計測
  components/   写真の表示、障害物・ルートの重ね描き、入力部品
  screens/      各画面（注意、スコア選択、撮影、確認、障害物の指定、結果、設定）
public/         PWA のマニフェスト、アイコン、サービスワーカー
docs/           GitHub Pages 用のビルド済みファイル（npm run build:pages の出力）
scripts/        esbuild によるビルド、簡易サーバー
```

## リアルタイム解析への移行について

- 計算は `computeRoutes(input)` という純粋な関数で、入力は「障害物の矩形」と「撮影条件」だけです。
  手動指定でも、AIの検出結果でも、同じ形式で渡せます。
- カメラは `useCamera()` の `grabFrame()` で任意のタイミングにフレームを取り出せます。
  第3段階では、これを一定間隔で呼び、検出器に渡します。
- 検出器は `src/analysis/source.ts` の `ObstacleSource` を実装します。結果には取得時刻（`capturedAt`）を持たせ、
  古い結果を最新として表示しないようにします。
- 写真上の位置はすべて割合（0〜1）で扱い、重ね描きは表示サイズに合わせて描くため、
  静止画でもカメラ映像でも同じ描画部品を使えます。
- 検出の確信度は、通過の推定確率には使いません（別の値として扱います）。

## プライバシー

写真は端末の中だけで処理し、サーバーへ送信しません。保存するのは、スコア帯、注意書きの確認済みフラグ、
画角の仮定の3つだけです（ブラウザーの localStorage）。
