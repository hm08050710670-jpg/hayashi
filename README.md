# GOLF ESCAPE AI（仮称）試作版：静止画解析＋リアルタイム解析（試験版）

林の中で、木の間を通過できそうな方向と、スコア帯別の推定確率を表示するスマートフォン向けWebアプリ（PWA）です。

- **静止画解析**：写真の上で木の位置を指定（手動、または自動検出＋手動修正）して計算します。
- **リアルタイム解析（試験版）**：カメラをかざしている間、映像から「奥が見通せる方向」を自動で探し、ルートと推定確率を更新します。
  撮影画面を開くと自動で始まります（安全確認は、アプリを開くたびに最初の1回だけ）。

自動検出は画像処理によるもので、AIモデルではありません。実際の林での精度は未検証です。

## 起動方法

Node.js 20 以上が必要です。

```bash
npm install
npm run dev        # 開発用サーバー（http://localhost:5173）
npm run build      # 本番用ファイルを dist/ に出力
npm run preview    # dist/ を手元で確認
npm test           # 計算ロジックと自動検出の単体テスト
```

スマートフォンでカメラを使うには、HTTPS で配信する必要があります（ブラウザーの仕様）。
`dist/` フォルダーの中身を、HTTPS に対応した静的ホスティングにそのまま置けば動きます。
リポジトリの `docs/` はビルド済みなので、試すだけならビルドは不要です。

### GitHub Pages で公開する

`docs/` フォルダーに、公開用のビルド済みファイルを入れてあります。次の設定をすると、
`https://<ユーザー名>.github.io/<リポジトリ名>/` で開けるようになり、スマートフォンでカメラも使えます。

1. GitHub のリポジトリで「Settings」→「Pages」を開く
2. 「Source」を「Deploy from a branch」にする
3. 「Branch」を `main`、フォルダーを `/docs` にして「Save」を押す
4. 1〜2分後に、同じ画面に表示されるURLを開く

フォルダーを `/ (root)` のままにした場合も、リポジトリ直下の `index.html` が `docs/` へ自動で移動するので開けます
（その場合のアプリのURLは `https://<ユーザー名>.github.io/<リポジトリ名>/docs/` になります）。

ソースを変更したときは、`npm run build:pages` で `docs/` を作り直してからコミットします。

### ビルドについての注意

このプロジェクトは React + TypeScript + Vite の構成です。ただし、作成時の環境では npm レジストリに接続できず、
Vite をインストールできませんでした。そのため同梱のビルド済みファイルは、同じソースを esbuild で直接ビルドしたものです
（`node scripts/build.mjs`）。`npm run dev` と `npm run build`（Vite）は、設定は標準的な内容ですが未実行です。
Vite でうまく動かない場合は、`npm run build:esbuild` と `npm run serve:dist` が代わりに使えます。
`docs/`（GitHub Pages 用）も、同じ esbuild のビルドで作っています。

## 実装済みの機能

- 利用上の注意（用途、ゴルフ規則、安全、確率の位置づけ）の表示
- 平均スコア（70台〜120台）の選択と端末内への保存、設定からの変更
- 背面カメラの起動、静止画の撮影、撮影画像の確認、再撮影
- 端末内の画像の読み込み（カメラを使えない場合の代替）
- 暗い写真、ブレ・ピンぼけの可能性がある写真への警告
- 障害物の手動指定：幹、枝（下端の高さ付き）、地面の障害物。選択、削除、1つ戻す、全消去
- 静止画での障害物の自動検出（試験版）と、手動での修正
- 指定した障害物からの候補ルートの計算（最大3件）と、写真上への矢印・帯・ラベルの表示
- スコア帯、ライ、距離、クラブに応じた推定確率（仮モデル）
- 判定不能の表示（障害物なし、枝がかかるのに距離・クラブが未入力）
- 通過不可の隙間を候補から外す処理
- 安全確認（前方に人がいる・確認できない場合はルートを表示しない）
- リアルタイム解析（試験版）
  - 撮影画面を開いたときの自動開始（安全確認は起動ごとに1回。「終了」を押すと、その起動中は自動で始めない）
  - 一時停止・再開・再解析・終了、開始ボタンからの再開
  - 映像への重ね描き（判定する高さの帯、障害物または未確認の範囲、ほかのルートの位置と数値）
  - 選んだルートの推定成功率を上部に大きく表示し、「10球打って何球通るか」をボールの数で示す
  - 選んだルートに「ショットのばらつきの扇」を重ねる（通る方向は緑、当たる方向は赤。濃さは飛ぶ頻度）
  - 状態の表示（確認中、カメラが動いている、暗すぎる、判定不能、表示中、一時停止中、解析が止まっている）
  - 数値の安定化（続けて同じ結果が出た範囲だけを採用、確率の平滑化）
  - 古い結果を最新として表示しない処理
  - 更新頻度の設定（毎秒2・4・8回）と、処理が重い端末での自動調整
- PWA（ホーム画面への追加、2回目以降のオフライン起動）

## 自動検出の考え方と限界

林の中から開けた場所（フェアウェイや空）を見ると、奥は明るく、手前の幹や枝は暗い影絵のように写ります。
この性質を使い、映像の中央付近の帯（目の高さあたり。画面に黄色い点線で表示）で、列ごとに次の2つを
両方満たすときだけ「見通せる」とし、それ以外はすべて「障害物または未確認」（斜線で表示）とします。

1. 帯の中に、奥の明るい背景が上下に連続して見えている。
2. その列の色が、帯の上と帯の中で変わっている
   （幹は上まで同じ色が続くため。日が当たった幹や白い幹を「開いている」と誤らないための確認。
   帯の下は、幹の根元や地面が入って幹でも色が変わるので、比較に使わない）。

幹そのものを当てにいくのではなく、「奥が見えている」と確認できた範囲だけを開いているとみなすので、
見落としは基本的に「通れない」側に倒れます。

**判定できない・誤りやすい場面**

- 奥が明るく写っていない（林の奥に向けている、曇天・夕方・日陰で明暗の差が小さい）→ 判定不能と表示します。
- 開けた方向でも、帯の上と色があまり変わらない場合（上まで空が続くなど）→ 未確認として扱います（通れるのに通れないと出る）。
- 幹の途中で色が変わる場合（苔、強い影、手前の葉）→ 開いていると誤る可能性が残ります。
- 帯の高さに入っていない低い枝・切り株・地面の障害物 → 検出しません。
- スマートフォンを下に向けた場合や屋内 → 意味のある結果になりません（床や壁の明暗に反応します）。

**検証の状況**：合成した林の映像と、公開されている林の画像1枚（シミュレーターで作られた写実的な画像）で
確認しただけです。実際のゴルフ場の林、実機のカメラ映像では未検証です。しきい値はすべて
`src/analysis/openingDetector.ts` と `src/analysis/live.ts` にまとめた仮の値です。

## 計算の考え方

1. 写真の横位置を、ボール付近から見た左右の角度に変換する（画角は仮定。設定で変更可能）。
2. 幹・地面の障害物がふさぐ角度の範囲を除いた残りを「隙間」とする。
3. 隙間の両側から、指定のずれ（0.5°）とボール半径分の余裕を引く。余裕を引いて残らない隙間は通過不可とする。
4. 打ち出し方向のばらつきを正規分布とみなし、隙間に収まる割合を求める。狙う方向は、この割合が最大になる向きを探す。
5. 枝がかかる範囲では、打ち出し高さが枝の下に収まる割合を掛ける（距離とクラブが必要。未入力なら判定不能）。
6. 大きなミス（チョロなど）の割合を差し引く。

表示する数値は「木の間を通過する推定確率」であり、林から完全に脱出できる確率ではありません。

### 仮パラメータ

スコア帯別のばらつき、ライの倍率、クラブ別の打ち出し角、色分けのしきい値などは、すべて
`src/model/params.ts` にまとめてあります。**実測データによる検証は行っていない仮の値です。**
アプリの設定画面でも、現在の値を一覧できます。

### この計算の限界

- 写真に写っていない範囲、指定していない奥の木や枝は計算に含まれません。
- 画角は機種やカメラのモードで変わります。仮定がずれると、角度の換算もずれます。
- カメラがボールの真上付近にあり、ほぼ水平に構えている前提です。離れた位置や大きく傾けた写真では誤差が増えます。
- 枝の高さの判定は、弾道を直線とみなした近似です。距離は「最初の木までの距離」を全障害物に共通で使います。

## 構成

```
src/
  model/        計算ロジック（画面に依存しない純粋な関数）
    params.ts     仮パラメータ
    geometry.ts   写真の位置と角度の変換、正規分布
    routes.ts     障害物 → 候補ルートと推定確率
    describe.ts   表示用の文言
    routes.test.ts 単体テスト
  analysis/     自動検出とリアルタイム解析（画面に依存しない純粋な処理）
    openingDetector.ts  1フレームから「見通せる方向」を検出
    live.ts             フレーム間の安定化、状態の判定、確率の平滑化
    analysis.test.ts    単体テスト
  camera/       カメラの起動・停止、フレームの取り出し、リアルタイム解析の繰り返し処理
  image/        画像の読み込み、明るさ・ブレの計測
  components/   写真の表示、障害物・ルートの重ね描き、入力部品
  screens/      各画面（注意、スコア選択、撮影、確認、障害物の指定、結果、設定）
public/         PWA のマニフェスト、アイコン、サービスワーカー
docs/           GitHub Pages 用のビルド済みファイル（npm run build:pages の出力）
scripts/        esbuild によるビルド、簡易サーバー
```

## 検出部分をAIモデルに差し替えるとき

- 検出は `detectOpenings(画素)` が「列ごとに見通せるか」を返すだけの関数です。
  同じ形（列ごとの 0/1 と、判定できたかどうか）を返すものに差し替えれば、安定化・ルート計算・表示はそのまま使えます。
- 計算は `computeRoutes(input)` という純粋な関数で、入力は「障害物の矩形」と「撮影条件」だけです。
- 検出の確信度は、通過の推定確率には使いません（別の値として扱います）。
- 解析は現在1回あたり1ミリ秒前後で、メインスレッドで実行しています。AIモデルに差し替える場合は
  処理が重くなるため、Web Worker への移動を検討してください。

## プライバシー

写真とカメラの映像は端末の中だけで処理し、サーバーへ送信しません。保存するのは、スコア帯、注意書きの確認済みフラグ、
画角の仮定、リアルタイム解析の更新頻度の4つだけです（ブラウザーの localStorage）。
